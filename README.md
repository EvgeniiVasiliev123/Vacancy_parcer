# Vacancy_Parser

Сбор вакансий с hh.ru в SQLite и SQL-аналитика рынка: какие навыки требуют аналитики данных, сколько им платят и как это меняется со временем. Результаты смотрятся в интерактивном дашборде (Streamlit).

> **Выводы:** *(заполните после первого сбора — 3–5 пунктов с цифрами, например: топ-5 навыков и их доли, медианные зарплаты по ролям и опыту, какие навыки дают прибавку к зарплате, доля удалёнки. Добавьте 1–2 скриншота дашборда.)*

## Что умеет

- **Сбор** через официальный API hh.ru: ретраи с бэкоффом, пауза между запросами, соблюдение лимита выдачи, без прокси.
- **Хранение в SQLite**: таблицы `vacancies`, `vacancy_skills`, `vacancy_seen`. Повторный запуск обновляет данные, не создаёт дубликатов и не перезапрашивает навыки уже известных вакансий. Снимки по датам дают динамику рынка.
- **Нормализация**: зарплата приводится к рублям «на руки» (середина вилки, курсы из `/dictionaries`, учёт gross/net), навыки приводятся к единому виду (регистр, алиасы вроде `postgres` → `postgresql`).
- **SQL-аналитика** (`vacancy_parser/sql/queries.sql`): медианы и квартили через оконные функции, топ навыков с долями (CTE + `RANK`), медиана зарплаты по навыкам, пары навыков (самосоединение), распределения опыта и графиков, динамика числа вакансий и доли навыка.
- **Дашборд** с фильтрами по роли и городу.
- **Тесты** (`pytest`) на нормализацию, идемпотентность записи и корректность SQL; CI в GitHub Actions.

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# hh.ru просит указывать приложение и контакт
export HH_USER_AGENT="VacancyParser/1.0 (your@email.com)"
# export HH_TOKEN=...   # если для вашего доступа к API нужна авторизация

python -m vacancy_parser collect --roles "Аналитик данных" "BI-аналитик" --areas 1 2 --period 30 --pages 5
python -m vacancy_parser report            # сводка в консоли
streamlit run dashboard.py                 # дашборд
pytest -q                                  # тесты
```

Полезные параметры `collect`: `--title-keywords аналитик analyst` (отсекает нерелевантные вакансии по названию), `--no-skills` (быстрый сбор без навыков), `--db путь.db`. Запускайте сбор регулярно (раз в неделю): так накапливается динамика.

## Структура

```
vacancy_parser/
  hh_client.py   клиент API (ретраи, паузы)
  normalize.py   зарплаты, навыки, плоская запись вакансии
  collector.py   поиск -> нормализация -> запись в БД
  db.py          подключение, upsert, загрузка запросов
  analytics.py   запуск именованных SQL-запросов -> DataFrame
  cli.py         команды collect / report
  sql/schema.sql, sql/queries.sql
dashboard.py     Streamlit
tests/           pytest
```

## Ограничения (важно для интерпретации)

- Зарплата указана не во всех вакансиях, выводы о деньгах относятся только к ним (доля показана в дашборде и в запросе `salary_coverage`).
- Вилка сводится к середине, а сами зарплаты на hh.ru заявленные, а не фактические.
- Вакансия, найденная по нескольким запросам, хранится один раз с ролью первого запроса.
- Курсы валют берутся из справочника hh.ru на момент сбора. Проверьте актуальные правила и условия доступа API hh.ru перед массовым сбором.
